# 快速体验

目标：让你在 10 分钟内把服务跑起来，**在浏览器里看到自己的周课表**，并亲手调用一遍全部主要接口。

## 前置

```bash
# 1) 一次性初始化数据库与账号（需要 root）
sudo bash scripts/init_db.sh

# 2) 编译 + 跑单元测试
bash scripts/build.sh
```

## 方式零：先看课表（最直观）

```bash
./build/campus_server        # 启动服务（默认自研 epoll 引擎）
```

然后浏览器打开 **<http://127.0.0.1:8080/>** ：

1. 学号和密码已预填演示账号（`2024001` / `secret123`），点「登录并同步课表」；
2. 页面会自己走完 `登录 → 同步 → 拉课表`，然后把课次画成**周课表**（周一到周日 × 节次）；
3. 单双周和不在这周上的课会显示成灰色，鼠标悬停能看到教师、地点、周次；
4. 上面还能切换「查看第几周」，勾上「按周次过滤」就能看出单周课/双周课的差别。

这个页面不依赖任何前端框架或 CDN，就是一段原生 JS + 本服务的 REST 接口，
所以 Android 客户端将来可以直接复用同一套接口。

## 方式一：一键引导演示（命令行版）

```bash
bash scripts/demo.sh          # 跑完自动停服务
bash scripts/demo.sh --keep   # 跑完保持运行，方便你用浏览器点
```

这个脚本会把下面 12 步**边执行边解释**，包括每一步为什么这样设计：

| 步骤 | 做了什么 |
|---|---|
| 0 | 检查 MySQL 是否在跑 |
| 1 | 编译（如果还没编译） |
| 2 | 启动服务（默认自研 epoll 引擎） |
| 3 | `GET /api/version` 看引擎、`GET /api/health` 看连接池与缓存 |
| 4 | 不带 token 访问受保护接口 → `401` |
| 5 | 用教务账号换 JWT（演示账号 `2024001` / `secret123`） |
| 6 | `POST /api/sync` 从模拟教务系统同步课表 |
| 7 | 再同步一次 → `changeCount=0`（幂等） |
| 8 | `GET /api/courses?semester=...` 查询课表 |
| 9 | 新增一门课（`source=manual`，不会被同步覆盖） |
| 10 | 故意犯两个错：重复课程号 → `409`；课内时间冲突 → `400` |
| 11 | 删掉刚建的课 |
| 12 | 连打写接口 → 观察 `429` 限流 |

## 方式二：Docker 一键起（不需要本机装 MySQL）

```bash
docker compose up -d --build
docker compose ps                              # 两个容器都应是 healthy
curl http://127.0.0.1:8080/api/health
docker compose logs -f campus-server
docker compose down -v                         # 连数据卷一起清掉
```

## 方式三：手动逐条调用

```bash
BASE=http://127.0.0.1:8080

# 1. 探活（不需要鉴权）
curl -s $BASE/api/health

# 2. 看这次跑的是哪个 HTTP 引擎（net = 自研网络库 / httplib = 对照组）
curl -s $BASE/api/version

# 3. 登录换 JWT（密码只在这一次出现）
TOKEN=$(curl -s -X POST $BASE/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"studentId":"2024001","password":"secret123","adapter":"mock"}' | jq -r .token)

# 4. 从教务系统同步课表（mock = 进程内模拟；adapter 也可用 http，需另起 mock_portal）
curl -s -X POST $BASE/api/sync -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"semester":"2026-2027-1","adapter":"mock"}'

# 5. 查课表
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/api/courses?semester=2026-2027-1" | jq

# 6. 新增一门课（含课次）
curl -s -X POST $BASE/api/courses -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"操作系统","code":"CS2001","teacher":"张老师","credits":3.5,
       "semester":"2026-2027-1",
       "sessions":[{"dayOfWeek":2,"startPeriod":3,"endPeriod":4,
                    "weeks":{"from":1,"to":16,"parity":0},"location":"教学楼A301"}]}'

# 7. 改 / 删（PUT / DELETE /api/courses/{id}）
curl -s -X DELETE -H "Authorization: Bearer $TOKEN" $BASE/api/courses/1
```

想看浏览器效果：`/api/health` 与 `/api/version` 不需要 token，直接在浏览器里打开即可；
其它接口需要 `Authorization: Bearer <token>` 头，用 curl 更方便。

## 返回值怎么读

成功时返回业务 JSON（例如 `{"total":3,"items":[...]}`）。

失败时统一是这个形状，`code` 与 HTTP 状态码一致：

```json
{"code":409,"error":"conflict","message":"课程号 CS2001 在学期 2026-2027-1 已存在"}
```

| HTTP | `error` | 什么时候出现 |
|---|---|---|
| 400 | `invalid_argument` | JSON 格式错误、缺字段、课内时间冲突 |
| 401 | `unauthorized` | 缺 token / token 伪造 / token 过期 |
| 404 | `not_found` | 课程不存在，或路径本身不存在 |
| 409 | `conflict` | 课程号 + 学期 唯一键冲突 |
| 429 | `too_many_requests` | 写接口或同步接口触发限流（响应头带 `Retry-After`） |
| 500 | `internal_error` / `database_error` | 服务端异常或数据库不可用 |

## 换个 HTTP 引擎跑同一条链路

```bash
CAMPUS_HTTP_ENGINE=httplib ./build/campus_server     # 对照组
CAMPUS_HTTP_ENGINE=net CAMPUS_HTTP_WORKERS=16 ./build/campus_server   # 自研引擎 + 16 worker
```

两者跑的是同一份业务代码（`api/dispatcher.cpp`），所以接口行为完全一致；
`bash scripts/bench_engine.sh` 负责量化它们的差异。
