## 重要提醒：换模型的时机（已执行）

epoll 网络库第一版（单线程 + 水平触发 + 增量解析 + 定时器轮）已用更强的模型完成。

**后续的硬骨头——边缘触发（ET）与多线程 Reactor（SO_REUSEPORT）——继续沿用强模型。**
原因：ET 要求每次读写都读到 EAGAIN，漏一个事件就是难查的 bug；多线程 Reactor 涉及
连接亲和性、负载均衡和锁粒度，复杂度都很高，且只能在 WSL 里验证、调试轮次多。

## 一、项目定位

一个**校园课表系统**：C++ 后端服务 + Android 客户端 + 自建模拟教务系统。

不对接任何真实学校系统。这样做有三个好处：

1. 没有合规风险，不需要碰真实账号密码；
2. 全链路（登录 → 抓取 → 解析 → 入库 → 变动检测 → 下发）都能真跑起来，不是假数据；
3. 可以自己造「教务系统改版」的场景，演示适配层架构。

**重心分配：后端 80%，客户端 20%。** 客户端由 AI 编写，保证能演示即可。

## 二、技术选型（按「能学会」优先）

| 层 | 选型 | 为什么 |
|---|---|---|
| 语言 | C++20 | 岗位对口 |
| 构建 | CMake + Ninja + ccache | C++ 工程标配，写进简历 |
| HTTP 框架 | cpp-httplib（起步） | 头文件库、零学习成本，先跑通再看内部 |
| JSON | nlohmann/json | 最常用的 C++ JSON 库 |
| 日志 | spdlog | 高性能结构化日志 |
| 数据库 | MySQL 8.0 | 你已经了解，资料最多 |
| 缓存 | Redis 7 | 会话与热点数据 |
| 测试 | GoogleTest + Catch2 | 工程素养 |
| 压测 | ab / wrk | 产出简历上的性能数字 |
| 部署 | Docker | 加分项 |

> 为什么不用 Drogon 起步？Drogon 依赖重、异步模型复杂，在 C++ 基础不牢时容易卡在编译错误上。
> 等到台阶 7 熟悉了再迁移，**「从同步模型重构到异步模型，QPS 提升 X 倍」本身就是一段很好的面试素材**。

## 三、八个台阶

每个台阶都是「能跑的东西 + 明确的知识点 + 一个验收标准」。

### ✅ 台阶 0：环境（已完成）

- WSL2 + Ubuntu 24.04、CMake、Ninja、GDB、ccache
- MySQL 8.0、Redis 7 已安装并设为开机自启
- 项目骨架编译通过，`/api/health` 可访问

### 台阶 1 · 一周：把课表变成 C++ 对象

**目标**：定义课程数据结构，从本地 JSON 文件读出课表并返回。

| 项目 | 内容 |
|---|---|
| 接口 | `GET /api/courses` |
| 学 C++ | `struct`/`class`、值语义、`const` 正确性、`std::vector`、`std::string_view`、聚合初始化、`nlohmann/json` 序列化 |
| 验收 | 接口返回一门课的完整信息（课程名/教师/地点/周次/节次/单双周） |

**这一步为什么重要**：你以为自己「学过 C++」，但真动手会发现连「要不要传引用」都拿不准。这一周就是在补这个。

### 台阶 2 · 一至两周：接上 MySQL

**目标**：设计 `users`、`courses`、`course_sessions` 三张表，读写走数据库。

| 项目 | 内容 |
|---|---|
| 接口 | `GET /api/courses`、`POST /api/courses`、`DELETE /api/courses/{id}` |
| 学 C++ | RAII、`std::unique_ptr`/`shared_ptr`、移动语义、异常安全、资源所有权 |
| 学数据库 | 表设计、索引、预编译语句防 SQL 注入、事务 |
| 验收 | 用 `curl` 增删查改，数据真实落库 |

**关键练习**：把 MySQL 连接封装成一个 RAII 类，析构时自动释放。这是 C++ 面试的必考思路。

### 台阶 3 · 一至两周：可插拔的教务适配器

**目标**：写一个模拟教务系统（独立的 HTTP 服务），后端通过适配器从它拉取课表。

| 项目 | 内容 |
|---|---|
| 接口 | `POST /api/sync`、`POST /api/login` |
| 学 C++ | 虚函数、多态、纯虚接口、虚析构、工厂模式、`unique_ptr` 持有基类指针 |
| 学工程 | HTTP 客户端调用、错误码设计、重试 |
| 验收 | 调一次 `/api/sync`，课表从模拟教务系统流进 MySQL |

**这是简历的核心亮点**：所有学校共用一个 `PortalAdapter` 接口，每接一所学校只加一个实现类。

### 台阶 4 · 一周：课表变动检测

**目标**：对比同步前后的课表，产出「换教室 / 换时间 / 换老师 / 停课」事件。

| 项目 | 内容 |
|---|---|
| 接口 | `GET /api/changes` |
| 学 C++ | `std::map`/`set`、`std::sort`、`find_if`、自定义比较器、`std::chrono` 时间处理 |
| 验收 | 手动改模拟教务的课表，同步后能准确报出变动 |

**面试加分**：这不是 CRUD 能替代的能力，讲清楚「怎么定义两门课是同一门课」这个问题，面试官会记住你。

### 台阶 5 · 一至两周：并发（分水岭）

**目标**：线程池 + 数据库连接池 + Redis 缓存 + JWT 鉴权。

| 项目 | 内容 |
|---|---|
| 学 C++ | `std::thread`、`mutex`、`condition_variable`、`atomic`、`lock_guard`、任务队列、线程安全单例 |
| 学系统 | 上下文切换、锁竞争、死锁四条件 |
| 验收 | 并发请求下数据不出错；用 `helgrind` 或 ThreadSanitizer 无告警 |

**这一步是从「学生作业」到「工程项目」的分界线。** 前面的代码写得再漂亮，这一步不做，简历上就还是个玩具。

### 台阶 6 · 一周：压测与优化

**目标**：拿到真实的性能数字，并知道瓶颈在哪。

| 项目 | 内容 |
|---|---|
| 工具 | `ab` / `wrk` 压测，`valgrind --tool=callgrind` 找热点，`perf` 看火焰图 |
| 优化方向 | 连接复用、减少拷贝（`std::move`/`string_view`）、批量 SQL、缓存命中率 |
| 验收 | 一份压测报告：QPS、P99 延迟、内存占用、优化前后对比 |

**简历上那行「P99 延迟从 120ms 降到 18ms」就来自这里。** 没有这步，简历只能写「实现了 XX 功能」。

### 台阶 7 · 两周以上：亮点工程（选做，但强烈建议）

二选一：

- **A. 自研 epoll Reactor 网络库**：非阻塞 IO + 事件循环 + 线程池 + 定时器轮
  → 面试含金量最高，能聊透 TCP、epoll 水平/边缘触发、Reactor 模式
- **B. 用 Drogon 重构现有服务**：对比同步/异步模型的 QPS 差异
  → 工程量小，也能产出漂亮的对比数据

### 台阶 8 · 一周：Android 客户端

由 AI 编写，只保证「能装、能看课表、能演示」。你不必理解 Kotlin 细节，面试时说明「客户端由我完成后端接口后配套实现」即可。

## 四、贯穿全程的习惯

1. **每个台阶写测试**：GoogleTest 写单元测试，接口用 `curl`/脚本做集成测试。
2. **每个台阶打 git tag**：`git tag v0.1-课程结构`，简历上的演进过程一目了然。
3. **每做完一台阶写一页笔记**：记「我踩了什么坑、怎么解决的」。面试前看这一本就够了。
